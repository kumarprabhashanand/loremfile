## Executive summary

**Decision: Approve with changes.** The architecture (R2 objects behind Cloudflare, no compute in the request path, manifest-as-lock, releases-as-backup) is the right one for the stated goals and is well argued; the CORS/caching design is sound (verified, A-6e/A-X17). It should not be built exactly as written, because several load-bearing vendor facts are wrong and a few mechanisms in the infra/CI/runbook do not work as described. Top five issues (after the 11:02–11:06 revisions):

1. **Major — the "query string cannot be ignored on Free" premise is wrong** (docs/02:108, 03:113, 08:215, 16:66, 19:42). "Ignore query string" is available on all plans in Cache Rules. ADR-013, threat T6, the runbook's strip-query redirect and the worst-case cost table are built on a false constraint; the fix is one line in the cache rule and removes the accidental-cache-bust cost entirely (B-1).
2. **Major — the primary cost control does not exist on this plan, and the cost model has gaps.** The "Usage Based Billing" notification (REQ-21, G4, T6, RISK-03, 08:43) is documented as "Professional plans or higher / Pay-as-you-go accounts only"; without it the first signal of a spike is the weekly session. The model also omits low-rate botnets below DDoS thresholds and random-404-path busting (C-4).
3. **Major — immutability and recovery are weaker than stated.** Immutability is enforced only in code paths while T2 can overwrite/delete every object (R2 bucket locks are not used, B-3/C-6); the DR target "one working day on a new account" is unreachable while the Registrar domain lives in the lost account (B-7); takedown leaves removed bytes in public GitHub Release assets (C-5).
4. **Major — the pipeline will not run as specified on first use:** the toolchain image has no `git`/`gh` although every job runs inside it and the revised workflows now depend on git history (06:170, 09:60,117,127-131) (B-5); `browser_cache_ttl: 0` is reportedly rejected on non-Enterprise zones (08:61, B-10); the token permissions for Single Redirects, Bot Management, DNSSEC and Tiered Cache are still `[VERIFY]` placeholders (08:40, 08:196-208, A-5/A-9b); scheduled workflows are auto-disabled after 60 days without repository activity, which negates RISK-10 (09:180, 17:16, B-6).
5. **Major — the markup-fixture CSP and the header rules need adjustment:** `default-src 'none'` breaks rendering of the HTML/SVG fixtures it protects (C-3); the suffix-keyed header rules silently depend on URL normalization staying on, which is neither in desired state nor audited (C-2).

Secondary: P1 scope (417–420 files, 05:12/05:290) is ~2.5× the 165 the original draft quoted, with an M3 estimate (30 h) that is not credible for ~50 generator/validator pairs (B-2); the 11:02–11:10 revisions fixed B-4, B-8, B-13, B-17 and consistency items E-1, E-3, E-4, E-6, E-8, E-10, E-15, E-18, E-19, E-21, E-22 — they are kept below marked Resolved. Remaining consistency items: E-2 (≈ 420 vs 417), E-5, E-7, E-11, E-12, E-16, E-17, E-20.
