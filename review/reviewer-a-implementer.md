# Reviewer A — "Implement this end to end, you cannot ask anyone anything"

Reviewer role: junior engineer / coding agent, fresh eyes. Scope: `README.md` and `docs/00` … `docs/19` (all 21 files read completely; cross-checked with `grep -n`, a Python regex check of every fixture name in `docs/05` against the grammar in `docs/03` §1, a P1 recount of `docs/05` §3, and five vendor-doc lookups where a fact changed a severity).

## Executive summary (5 lines)

1. **Could I implement this end to end without asking anyone? No.** I could build M1 (skeleton/toolchain) and most of M3 (generators) from these docs, but I could not get a correct first deploy or a correct PR flow, and many fixture bytes would be my guesses — and guesses become permanent under the immutability policy.
2. **Blocker 1 — the build/deploy pipeline cannot upload anything as written.** `build` "generates only fixtures whose path is not yet in the manifest" (06:124, 09:62), the add-a-fixture flow commits the manifest entry in the PR (11:123), so on `main` the deploy job generates nothing and `upload --fixtures` (09:108, 09:183) has no local bytes for keys missing in R2; CI also never validates a fixture whose manifest entry the PR adds (REQ-11 becomes vacuous).
3. **Blocker 2 — `deploy.yml` fails on every run:** `manifest update` rewrites `generated_at` (04:14) and the next step is `git diff --exit-code -- manifest.json` (09:105–106). `toolchain_image` (04:19) has the same problem on every toolchain bump.
4. **Blocker 3 — M2.3/M2.4 need T1/T2 on the engineer's machine** (15:38–39, 11:70) while the security model says tokens live "only in GitHub env secrets" (10:27); the temp-object cleanup in M2.4 needs a delete path the uploader deliberately does not have (09:185). No procedure covers this.
5. Beyond the blockers: ~30 fixtures are "sized" with no recipe, the edge truncation sources are ambiguous, the datasets/corpora are unspecified, the P1 counts in `docs/05` §5 disagree with the rows in `docs/05` §3 (my recount: 417 rows vs "≈ 374" vs "~165"), the transform-rule count is 6 / 5 / 3 depending on the document, and three milestone cross-references point at the wrong milestone.

## Findings

Severity: **Blocker** = cannot proceed / pipeline broken as written; **Major** = would have to guess something that is hard to change later or that blocks a milestone; **Minor** = inconsistency or gap that costs time; **Question** = needs a human but has a sensible default.
