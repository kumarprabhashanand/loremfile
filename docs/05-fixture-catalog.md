# 05 — Fixture Catalog v1

This document is the authoritative list of fixtures. It is transcribed into `catalog/*.yaml` (one file per format) and the YAML is what the pipeline reads; if the two ever disagree, fix the YAML and this document together in the same PR.

## 1. Global rules

1. **Synthetic only.** Text is Lorem Ipsum (public domain) or generated. People data uses fixed fictional name lists, `@example.com` / `@example.org` emails, US `555-01xx` and UK `+44 7700 900xxx` reserved phone ranges, fictional street addresses, real country codes, birth dates between 1950 and 2005. No real names of real people, no real addresses, no card numbers, no IBANs, no government IDs.
2. **Deterministic.** Every generator receives `ctx.seed = sha256("loremfile:" + path)` (the full fixture path, e.g. `bin/1mb.bin`), sees all clocks fixed at `2020-01-01T00:00:00Z` (`SOURCE_DATE_EPOCH=1577836800`), and never reads the environment or the network (`06` §4).
3. **Safe.** No scripts in PDFs; no external entity references in XML; no executables (no MZ/ELF/Mach-O magic); no EICAR string; no decompression ratios above 1000:1 in archives (`zip64-70000-empty-files.zip` is the largest ratio and is whitelisted with its ratio recorded); no private keys; no macros (`.xlsm`, `.docm` are excluded).
4. **Sizes.** ≤ 100,000,000 bytes per fixture. `bin/` and `txt/lorem-*` are exact; `-plus-1`/`-minus-1` are exact boundaries; other size-named fixtures are `approx` (±5 %).
5. **Every fixture has a one-line description** written for a reader deciding whether it fits, and `tags` from the controlled vocabulary.
6. **Phases.** Rows marked phase 1 total ≈ 417 files / ≈ 1.06 GB (§5). The **launch set (P1)** is the explicit list in §9 (229 files, ≈ 620 MB, every family represented); the remaining phase-1 rows are **P1b**, added in batches right after launch (`15` M7). Phase 2 (P2) is the roadmap. Anything not in this document needs a catalog PR that also updates this document.
7. **Charsets.** Every text-like fixture's `mime` carries an explicit charset; the default appended by the catalog loader is `utf-8`. The only overrides are: `txt/utf16le-bom.txt`, `txt/utf16be-bom.txt` → `text/plain; charset=utf-16`; `txt/utf32le-bom.txt` → `text/plain; charset=utf-32`; `txt/latin1.txt` → `text/plain; charset=iso-8859-1`; `txt/windows-1252.txt` → `text/plain; charset=windows-1252`; `txt/shift-jis.txt` → `text/plain; charset=shift_jis`; `txt/gb2312.txt` → `text/plain; charset=gb2312`; `csv/people-10-latin1.csv` → `text/csv; charset=iso-8859-1`; `csv/people-10-utf16le.csv` → `text/csv; charset=utf-16`; `xml/utf16.xml` → `application/xml; charset=utf-16`; `xhtml` → `application/xhtml+xml; charset=utf-8`. Edge fixtures with `defect: invalid-encoding` keep the charset their name claims.
8. **Sizes for `-plus-1`/`-minus-1`** exist only in `bin/`. Sizing recipes for every size-named fixture are in §6.

## 2. Shared synthetic datasets

Generated by `datasets.py` from a fixed seed and word lists checked into `src/loremfile/data/wordlists/` (all synthetic, CC0: 200 first names and 200 family names spanning common Latin-script names from several cultures, 100 real city names with their real ISO-3166 alpha-2 country codes across 46 countries (the lists were written in M1.7; a city maps to exactly one country, which `tests/unit/test_datasets.py` asserts), 100 invented street names such as "Maple Court", 60 accented Latin-1 words for `bio`). Names are facts and combinations are random; at 100,000 rows some common name/city pairs will coincide with real people, but no row identifies anyone because email, phone, street, dates and biography are all invented (this is the reading of the content policy in `13` §5). Rows are generated sequentially from one RNG stream seeded with `sha256("loremfile:dataset:people")`, so **`people-10` is the first 10 rows of `people-1000`, which is the first 1000 rows of `people-100k`** (prefix property; cross-format tests rely on it). Each format generator serialises the same rows.

**people** — columns and value rules:

| Column | Type | Rule |
|---|---|---|
| `id` | int | 1…n |
| `first_name`, `last_name` | str | from the word lists |
| `email` | str | `{first}.{last}{id}@example.com` (lowercase, ASCII-folded); every 10th row uses `@example.org` |
| `phone` | str | US `+1-555-01{00–99}` for US rows, UK `+44 7700 900{000–999}` otherwise (reserved fiction ranges) |
| `street`, `city`, `country` | str | street = `{number 1–9999} {street name}`; city and country from the same list row |
| `birth_date` | date | uniform 1950-01-01 … 2005-12-31 |
| `signup_at` | datetime (UTC) | uniform 2015-01-01 … 2019-12-31, second precision, ISO 8601 `Z` |
| `balance` | decimal(12,2) | log-normal, median 250.00, 5 % negative |
| `is_active` | bool | 80 % true |
| `tags` | list[str] | 0–3 from 12 fixed tags |
| `bio` | str | 0–200 chars built from Lorem Ipsum words plus the accented Latin-1 word list; **every character is encodable in ISO-8859-1 and Windows-1252**, so the same rows serialise into every charset variant |

**orders** (seed `loremfile:dataset:orders`): `order_id` 1…n, `person_id` uniform over 1…1000, `amount` decimal(10,2) 1.00–2000.00, `currency` from {USD, EUR, GBP, JPY, INR, BRL}, `status` from {pending, paid, shipped, cancelled, refunded} weighted 10/50/30/5/5, `created_at` uniform 2019. Sizes: 100, 10k.

**products** (seed `loremfile:dataset:products`): `sku` `LF-{00001…}`, `name` two lorem words title-cased, `category` from 8 fixed values, `price` decimal(8,2), `stock` int 0–500, `attributes` nested object `{color, weight_g, dimensions_mm: {w,h,d}, tags: [...]}`. Size: 100.

## 6. Sizing recipes (every size-named fixture)

`util/sizing.py` provides `fit(target, tolerance, make, n0, n_min, n_max, max_iter=12)`: `make(n)` builds the file from one monotone integer parameter `n`; `fit` starts at `n0`, scales `n` proportionally to `target / len(make(n))` (secant step, then bisection once bracketed) and stops when `|len - target| ≤ tolerance × target`. If it cannot converge in `max_iter` it fails the build with the closest attempt — a fixture is never published outside its size class. `tolerance` is 0.05 for `approx`. Exact classes do not use `fit`; they compute the size arithmetically.
