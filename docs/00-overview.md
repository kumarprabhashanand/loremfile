# 00 — Overview

## 1. One-paragraph summary

loremfile.dev serves a curated, permanently stable set of synthetic files — PDFs, images, audio, video, office documents, data files, archives, fonts, text encodings, raw byte blobs and deliberately malformed edge cases — at predictable URLs such as `https://loremfile.dev/pdf/a4-3pages.pdf`. Every file is generated by open-source scripts, released under CC0, served with open CORS, byte-range support and one-year immutable caching, and described in a machine-readable `manifest.json` with SHA-256 hashes. There is no server, no database, no login and no upload: the whole service is objects in a Cloudflare R2 bucket behind Cloudflare's CDN, plus a static website in the same bucket.

## 2. Why it exists (evidence)

Developers and agents need known files to test uploads, parsers, players, viewers, size limits and content-type handling. Today they hotlink whatever they can find. Counts below are files on public GitHub that reference each URL, measured with GitHub code search on 2026-09-06; status was checked the same day.

| Commonly hotlinked URL | Files on public GitHub | Status on 2026-09-06 |
|---|---|---|
| Google's unofficial `gtv-videos-bucket/sample/BigBuckBunny.mp4` | 17,728 | HTTP 403 |
| `soundhelix.com/examples/mp3/…` demo MP3s | 14,368 | Works, no CORS header |
| `w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf` | 7,920 | Works |
| `sample-videos.com/…` | 3,120 | Broken TLS certificate |
| `africau.edu/images/default/sample.pdf` | 1,520 | HTTP 404 |
| `picsum.photos/200` (the clean model for images) | 63,232 | Works |

Existing "sample file" websites are ad-funded (filesamples.com, file-examples.com, sample-files.com, freetestdata.com, getsamplefiles.com, learningcontainer.com all load ad networks), so hotlinking undercuts their revenue: filesamples.com restricts CORS to its own origin; samplelib.com returns HTTP 400 when the `Referer` is another site; testfiles.dev is a browser-side generator with no hotlink URLs; `mathiasbynens/small` is public-domain but consists only of smallest-valid files on raw GitHub with no manifest. None offers **CC0 + open CORS + hotlinking welcome + manifest + edge cases + no ads**. That combination is what made picsum.photos the default for images.

## 3. Goals

| ID | Goal | Measure |
|---|---|---|
| G1 | Be the URL people paste when they need "a sample X file" | Inbound hotlinks and search ranking for "sample pdf file url", "test mp4 url", etc. |
| G2 | Be usable by machines without a human | `manifest.json`, `llms.txt`, stable paths, predictable headers |
| G3 | Never break a published URL | Zero byte changes at a published path, ever (see immutability policy) |
| G4 | Cost ≈ domain renewal only | Stay inside Cloudflare free tiers; automated daily cost check (R2 operations) opens an issue above 5 M reads/month |
| G5 | Maintenance ≤ 1 hour/week after launch | Automation does deploys, health checks, dependency updates |
| G6 | Survive abuse and attacks with no human on call | No origin server; edge caching; rate limiting; no write path |

## 4. Non-goals (v1)

- User uploads, accounts, comments, analytics dashboards, paid tiers.
- On-demand generation of arbitrary files (a small fixed set of dynamic endpoints is a Phase 3 extension, see `14-roadmap-and-extensions.md`).
- Hostile or malicious test files (EICAR, zip bombs, exploit PoCs, script-bearing PDFs).
- Real private keys. (The Ed25519 test certificate's key is derived from a public seed and is therefore itself public; the fixture says so and uses `fixture.example`, never the production hostname.) These are explicitly excluded from the main domain (see `13-legal-and-policy.md` §5) and considered only for a separate domain in Phase 4.
- Real-world copyrighted or licensed content (no Big Buck Bunny, no stock photos, no third-party fonts). Everything is generated.
- Serving as a general CDN for third-party assets.

## 7. Vocabulary

| Term | Meaning |
|---|---|
| **Fixture** | One published file with a permanent path, e.g. `pdf/a4-3pages.pdf`. |
| **Format** | First path segment; the container/type family a fixture belongs to (`pdf`, `mp4`, `zip`, `bin`, `edge`, …). |
| **Catalog** | The declarative YAML files in `catalog/` that define which fixtures exist and how to generate them. |
| **Manifest** | `manifest.json`: the generated, committed record of every published fixture including SHA-256. Acts as a lock file. |
| **Lock check** | CI rule: an existing manifest entry may never change bytes/hash/path. |
| **Site** | The static HTML documentation website, also stored as objects in the bucket. |
| **Toolchain image** | The pinned Docker image in which all generation runs, for reproducibility. |
| **Edge case** | A fixture that is deliberately invalid, truncated, mismatched or unusual. Lives under `edge/` if it is not a valid instance of its format. |
| **Desired state** | JSON files under `infra/` describing every Cloudflare setting; applied and audited by scripts. |
| **Phase** | P1 = the launch set (the explicit list in `05` §9, 228 files); P1b = the remaining catalog rows marked phase 1, added in batches right after launch; P2–P4 = roadmap. Each fixture in the catalog carries its phase. |
