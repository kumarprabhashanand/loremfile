# 10 — Security

## 1. Security goals

1. Nobody can change or remove a published fixture except through a reviewed commit on `main`.
2. The domain cannot be used to host attacker-controlled content, phishing, or executable code.
3. An attacker cannot make the owner pay a meaningful amount or take the service down for long.
4. Loss of any single credential is contained and recoverable within one weekly session.

## 2. Assets

| Asset | Why it matters |
|---|---|
| Cloudflare account (Registrar, DNS, R2, rules) | Owns everything at runtime; compromise = full takeover including the domain |
| GitHub repository and Actions secrets | Owns the deploy path; compromise = ability to publish new (not modified) objects and change site/infra |
| API tokens T1 (zone), T2 (R2 objects), T4 (analytics, read-only) | Scoped write access; T4 scoped read access |
| Toolchain image and Python lock | Supply chain for generated bytes |
| The domain's reputation (Safe Browsing, mail, AV vendors) | A blacklisting breaks every user |
| Owner's mailbox and 2FA devices | Recovery path |

## 3. Threat model and controls

| # | Threat | Likelihood | Impact | Controls |
|---|---|---|---|---|
| T1 | Cloudflare account takeover (phishing, credential stuffing) | Low | Critical | Hardware-key/passkey 2FA + authenticator backup; unique strong password; recovery codes offline; Registrar transfer lock (default on); WHOIS redaction; login alerts; no shared accounts; the owner is the only member |
| T2 | GitHub account takeover | Low | High | 2FA with passkey; PR-only `main`; secrets only in `production` env bound to `main`; push protection; signed commits optional |
| T3 | Leaked T1/T2 token (log, laptop) | Medium | **High** for T2 without bucket locks (site defacement, content wipe — recoverable from Releases); Medium with locks | Tokens scoped to one zone / one bucket; 180-day expiry; rotation runbook; tokens exist only in GitHub environment secrets (every maintenance operation runs through `infra.yml`/`deploy.yml`, never from a laptop); CI logs mask secrets; **R2 bucket locks** make fixture prefixes read-only at the storage layer, so T2 can only add fixtures; site keys stay writable but are hashed daily against a rebuild of the deployed commit from the repository (never against anything stored in the bucket, which T2 could also rewrite); T1 cannot touch R2 or billing |
| T4 | Malicious PR (fork) tries to exfiltrate secrets or publish bad bytes | Medium | Medium | Fork PRs get no secrets; no `pull_request_target`; validators + policy scan; lock check; maintainer review; CODEOWNERS |
| T5 | Supply-chain compromise of a Python dependency or base image | Low | High | Hash-pinned lock; digest-pinned image; Dependabot PRs reviewed; determinism tests on image bumps; generated bytes validated by independent parsers; no network during generation |
| T6 | Bandwidth/ops amplification: attacker loops downloads of `100mb.bin`, requests random non-existent paths (each unique 404 is one R2 read, cached 3 min), or spreads requests over many IPs below DDoS thresholds | Medium | Low–Medium (cost) | R2 egress free; edge cache; query strings excluded from the cache key (so `?random` costs nothing); 100 MB cap; rate limit 300/10 s/IP; DDoS protection; daily automated R2-operations check opens a `cost` issue above 5 M reads month-to-date (the Free plan has no billing alert); incident playbook: ASN/country block via custom rule, Under Attack mode, disable the custom domain |
| T7 | Domain used as an XSS/phishing host via HTML/SVG fixtures | Low | High (reputation) | `Content-Security-Policy: sandbox; default-src 'none'; img-src … ; media-src … ; style-src 'unsafe-inline'; font-src …` on markup fixtures (inert: no scripts, forms, plugins, opaque origin); `nosniff`; `noindex`; no user-controlled content anywhere; policy scan rejects scripts and event handlers in SVG/HTML; fixtures that look like login pages are forbidden (policy §5) |
| T8 | Safe Browsing / AV flags the domain because of "malicious-looking" fixtures | Low | Critical | No EICAR, zip bombs, exploit PoCs, executables, macros, JS-bearing PDFs; `MZ` header fixture is text-only and whitelisted; hostile fixtures deferred to a separate domain (Phase 4) |
| T9 | Someone claims copyright on a fixture | Very low | Low | Everything generated; no third-party media; lorem text public domain; DejaVu used only for rendering labels (permissive licence); takedown procedure exists |
| T10 | Domain expiry / payment failure | Low | Critical | Auto-renew; card expiry reminder in runbook; health check warns at 45 days via RDAP; owner email alerts |
| T11 | Cloudflare account suspension (ToS, billing) | Very low | Critical | Serve large files only through R2, which is a Developer Platform product; the CDN terms require the Developer Platform "Paid Services" for video/large files and say nothing separately about free-tier R2, so keep usage honest and be ready to move to Workers Paid if asked; off-Cloudflare backups (GitHub Releases; optional S3) enable rebuilding a mirror in a day |
| T12 | R2 data loss or accidental delete | Very low | High | Bucket locks (indefinite, per format prefix) refuse deletes and overwrites; the tool's only delete paths are tombstoned keys (which require the owner to lift the lock) and `_probe/`; T2 cannot delete the bucket; GitHub Release archives; regenerable from source |
| T13 | Cache poisoning / header injection | Very low | Medium | No query-dependent behaviour; static objects; headers set by Cloudflare rules, not by origin logic |
| T14 | Subdomain takeover | Very low | Medium | Only `www` and mail records exist; audit.py lists DNS records and flags unknown ones |
| T15 | Abuse reports (someone hotlinks fixtures in spam) | Low | Low | Nothing to do: content is inert; `noindex`; Terms allow blocking abusive referrers if ever needed via a custom rule |
| T16 | Site defacement through T2 (site keys are writable) | Low | High (phishing page on the domain) | Strict site CSP; `health.yml` rebuilds the site from the checked-out commit (deterministic build) and hashes every live site key against it — the baseline is the repository, not a file in the bucket; a mismatch opens a `health` issue; `deploy.yml` `force_site` restores from a clean checkout; rotate T2 |
| T17 | Header rules bypassed by an encoded path if URL normalization is turned off | Very low | Medium | Normalization is in the desired state and audited; daily probes request `%2E`-encoded paths; optional response-type-keyed CSP rule |


**Accepted deviation, M0.4 (2026-09-08): the Cloudflare MCP OAuth session was used in place of T3.**
`08` §2 steps 6 and 8 called for minting an admin token (T3) and deleting it afterwards. Instead the
configuration was applied through the owner's authorised MCP session, so **no admin token ever existed
on a machine** — which is the outcome those two steps were protecting, achieved more completely than by
following them.

The deviation worth recording is the blast radius. That session carries **account-wide** scope, wider
than T3's design, on an account that also holds two unrelated production zones (`mcpreflex.dev`,
`shameher.com`). Mitigations actually applied, not merely intended: every call was scoped to the
`loremfile.dev` zone id, and both other zones were read back afterwards and confirmed unchanged. The
session could not mint credentials — `/user/tokens` returned `9109 Unauthorized`, which is correct for a
session that should not be able to create long-lived tokens.

**Standing rule for future infrastructure work through that session: scope every call to the zone id and
verify the untouched zones afterwards.** Recorded here so it is not rediscovered as an anomaly in a later
audit.

## 4. Credential inventory and rotation

| Credential | Where stored | Scope | Expiry | Rotation procedure (runbook §7.3) |
|---|---|---|---|---|
| Cloudflare login | Owner's password manager | Account | — | On suspicion |
| GitHub login | Owner's password manager | Account | — | On suspicion |
| T1 zone token | GitHub env secret | Zone: settings, rules, WAF, purge, DNS | 180 d | Create new → update secret → run `infra audit` → delete old |
| T2 R2 object token | GitHub env secret | Bucket objects RW (fixture prefixes are bucket-locked) | 180 d | Same, then `upload --dry-run` |
| T4 analytics token | GitHub env secret | Account analytics + zone analytics, read-only | 365 d | Same, then run `health.yml` |
| T3 setup admin token | Nowhere (deleted after setup) | Account R2 admin | 1 d | Re-create for bucket-level changes only |
| Email destination verification | Cloudflare | — | — | — |

## 5. Hardening checklist (completed in M5.4, re-checked quarterly)

- [ ] Cloudflare: 2FA hardware key + backup method; recovery codes stored offline; no other members; API tokens listed match the inventory; Registrar transfer lock on; auto-renew on; DNSSEC active.
- [ ] GitHub: 2FA; ruleset on `main` active; `production` environment restricted to `main`; Actions permissions restricted; secret scanning + push protection; Dependabot enabled; private vulnerability reporting enabled.
- [ ] Zone: all "must be off" features off (`infra audit` green); TLS 1.2+; HSTS by TLD; `always_use_https`.
- [ ] Bucket: public access only via the custom domain (r2.dev public URL **disabled**); CORS policy as specified; bucket lock rules present for every format prefix; no lifecycle rules; no other custom domains.
- [ ] Rules → Settings → Normalize incoming URLs: on.
- [ ] Mail: SPF via Email Routing; DMARC `p=reject`; no DKIM needed (no sending).
- [ ] Repo: no secrets in history (`gitleaks` run once in M1); `SECURITY.md` present; `security.txt` deployed.

## 6. Incident response (see runbook §7 for step-by-step)

| Scenario | First 10 minutes | Then |
|---|---|---|
| Cost spike / abuse | `cost` issue or DDoS mail → Cloudflare analytics → identify paths/ASNs → custom rule blocking the ASN or country, or block unknown-prefix paths; Under Attack mode if needed | Post-mortem issue; consider lowering the rate limit |
| Credential leak | Revoke token in Cloudflare; rotate; check audit log for changes; run `infra audit`; verify fixtures via `verify-live --mode full` | Rotate all tokens; review access |
| Safe Browsing warning | Identify flagged URL via Search Console; remove object (takedown procedure) ; request review | Root cause; policy update |
| Site defaced (site keys changed) | Daily site-integrity check flags it → re-run deploy with `force_site` from a clean checkout; rotate T2; inspect the R2 audit log | Post-mortem |
| Fixture bytes changed on R2 (should be impossible) | `verify-live --mode full` diff; restore from the release archive via `infra.yml` restore mode (`upload --restore`); rotate T2 | Post-mortem |

## 7. Disclosure policy (`/docs/security-policy`, referenced from security.txt)

Report via GitHub private vulnerability reporting or `security@loremfile.dev`. Acknowledgement within 7 days (the project has no on-call). No bounty. Please do not run volumetric tests against the service. In scope: anything that lets a third party change or remove content, execute script in the loremfile.dev origin, or inflate costs beyond the rate limit's intent. Out of scope: rate limiting itself, missing headers on 404 pages, findings that require a Cloudflare account compromise.

## 8. Credential loss and recovery

| Lost item | Effect | Recovery |
|---|---|---|
| Owner's 2FA device (Cloudflare or GitHub) | Cannot sign in | Recovery codes stored offline (M0.1); GitHub account recovery; register a second passkey right after |
| T1 or T2 expired (day 181) without rotation | `deploy.yml`, `infra.yml`, `audit.yml` fail; `health.yml` keeps running (it needs only T4) | `health.yml` opens a `rotation-due` issue 30 days before each token's recorded expiry (dates kept in `infra/token-expiry.json`); rotate per runbook §7.3 |
| T4 expired | Cost/usage step fails (health issue) | Rotate |
| Email Routing destination mailbox lost | Legal/security mail undeliverable | Owner updates the destination in Email Routing; GitHub Security Advisories remain as the second channel |
| GitHub `production` environment secrets (only the owner or repo admin can edit) | Rotation blocked | The engineer/agent needs admin on the repository (M0.3) |
